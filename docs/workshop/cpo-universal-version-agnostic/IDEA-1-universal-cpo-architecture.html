Universal CPO — Version-Agnostic Hosting Substrate

Idea 1 · Two tiers split by a versioned Environment Contract · three self-adapting outbound ports across the version boundary

Tier 1 — Universal Substrate

  • role: control-plane hosting runtime
  • • placement, PKI/identity, datastore
  • • connectivity, cloud infra, orchestration
  • • cross-cluster bridge (plumbing)
  • key: carries no target-version knowledge →
  •   already agnostic (live run proved 35/36)
  •   ships independently of the payload

Environment Contract — firewall

  • carries: primitives, not flags
  • • etcd endpoint · serving certs · kubeconfig
  • • konnectivity · config inputs · health sink
  • versioned by: CONTRACT ver, not OCP ver
  • • add-only, negotiated → churns slowly
  • dissolves: "ship independently" vs
  •   "version-safe" — the seam IS the fix

The 3 self-adapting ports

  • ① operand-config: mandatory version-gating
  •   (self-tracks live ver) → no unknown-flag
  • ② guest-API: discovery-gated SSA writes
  •   (OpenAPI v3) → no CRD-shape prune
  • ③ protocol: convergence-gated steps
  •   (observe/timeout) → no quiet stall
  • over all: structural enforcement + matrix
